# 새 서버 오픈 · 서버 이전 매뉴얼 (v3)

서버를 **새로 늘릴 때**, 또는 **다른 업체로 옮길 때** 이 순서대로만 하면 된다. PC는 **Windows** 기준이다.

| 순서 | 할 일 | 새 서버 | 서버 이전 | 시간 |
|---|---|---|---|---|
| 0 | 업체·상품 고르기 | ✅ | ✅ | — |
| 1 | 주문 | ✅ | ✅ | 5분 |
| 2 | 접속 + 비밀번호 바꾸기 | ✅ | ✅ | 3분 |
| 3 | **회선 품질 확인 (ping)** — 불합격이면 여기서 멈추고 해지 | ✅ | ✅ | 2분 |
| 4A | 설치 명령 1줄 | ✅ | — | 5~10분 |
| 4B | 옛 서버 데이터 통째로 옮기기 → 설치 | — | ✅ | 20~30분 |
| 5 | 웹 접속 · 서버명 | ✅ | ✅ | 2분 |
| 6 | 설치 후 확인 (BBR · CPU · ping) | ✅ | ✅ | 5분 |
| 7 | 채널·키 → 미디어 → 라이브 | ✅ | (이미 옮겨짐) | 파일 양에 따라 |
| 8 | **SSH 키 등록 — 2번 직후, 설치 전에 하는 게 가장 좋음** | ✅ | ✅ | 3분 |

> 막히거나 빨간 **[중단]**·영어 오류가 보이면 화면 글자를 그대로 복사해서 보내 주면 된다.
> 비밀번호·스트림 키는 **절대 채팅에 붙이지 않는다.**

## 0. 업체·상품 고르기

**기준 (live1 Contabo 실측에서 나온 것)**

| 기준 | 이유 |
|---|---|
| 4코어 / 8GB 이상 | 라이브 10개 = CPU 평균 약 30%. 코어 1개당 라이브 약 4~5개 |
| **트래픽 무제한** 또는 월 30TB 이상 | 라이브 1개 ≈ 5.3Mbps ≈ 월 1.7TB |
| **회선이 흔들리지 않을 것** | 거리보다 **흔들림**이 중요. 3단계 ping 으로 확인 |
| Ubuntu 24.04 | 설치 스크립트가 검증된 버전 (26.04 는 아직 X) |
| 예산 | 서버 1대(라이브 10개 이상)당 월 $10 이하 |

**현재 추천: OVHcloud VPS-2 2027** (4코어 / 8GB / 75GB NVMe / 트래픽 무제한 1Gbps)
- 약정 없음 $10, 12개월 약정 $8.50. 라이브 **16~20개** (CPU 기준).
- 디스크 75GB → 곡 5,000개 + 영상(5분짜리) 100개 ≈ 45GB. **50GB 까지만 쓰는 걸 목표**로 (업로드 중엔 임시로 더 씀).

**쓰면 안 되는 곳 / 피할 것**
- Contabo: 2026-11 live1 실측 — 3ms 거리인데 ping 이 최대 75~276ms 로 출렁여 라이브 10개가 동시에 밀림·"나쁨" 반복.
- OVH 의 Asia/Oceania 위치: 트래픽 무제한이 아님.
- 트래픽을 GB 단위로 따로 받는 곳 (AWS·Vultr 등): 24시간 송출엔 너무 비쌈.

## 1. 주문 (OVHcloud 예)

| 항목 | 고를 것 |
|---|---|
| 상품 | **VPS-2 2027** |
| 약정 | 처음엔 **No commitment** (3단계 합격·며칠 운영 뒤 12개월 약정으로 바꾸면 15% 할인) |
| 위치 | 유럽 또는 **캐나다 동부(Beauharnois)** — 둘 다 무제한. 아시아는 X |
| 이미지 | **Ubuntu 24.04** |
| 옵션 | 추가하지 않음 (매일 백업은 기본 포함) |
| 프로모션 코드 | 비워 둠 |

- 가격은 "세금 별도" 표기다. 결제 화면의 **최종 금액**을 확인한다.
- 첫 청구 전에 관리 화면 **결제/갱신** 에서 다음 달 금액이 그대로인지 한 번 확인한다.
- 주문 후 몇 분 안에 **접속 정보 메일**이 온다 (사용자 이름 `ubuntu` + 비밀번호). 서버 IP 는 메일 또는 OVH 관리 화면에 있다.

## 2. 접속 + 비밀번호 바꾸기

1. 키보드 **윈도우 키** → `powershell` → **Enter**
2. (OVH 는 `ubuntu`, Contabo 는 `root`)

```powershell
ssh ubuntu@서버IP
```

3. 처음엔 `yes` → **Enter**, 그다음 메일의 비밀번호 입력 → **Enter**
   - **입력해도 화면에 안 보이는 게 정상**. 붙여넣기는 **마우스 오른쪽 클릭**.
   - 처음 접속 때 바로 비밀번호를 바꾸라고 하면 (현재 → 새 것 → 새 것 한 번 더) 따라 한다.
4. 직접 바꾸려면:

```bash
passwd
```

   새 비밀번호는 **12자 이상, 영문 대소문자·숫자·기호 섞어서**. PC 에 안전하게 적어 둔다.
5. 관리자(root)로 바꾼다 — **이후 모든 명령은 이 상태에서**:

```bash
sudo -i
```

맨 아래 줄이 `root@…:~#` 로 바뀌면 된다.

## 3. 회선 품질 확인 (가장 중요 — 설치 전에)

라이브 없이 회선만 본다. **10분 간격으로 2~3번** 돌린다.

```bash
ping -c 30 -q 1.1.1.1
```

```bash
ping -4 -c 30 -q a.rtmps.youtube.com
```

마지막 줄 `rtt min/avg/max/mdev = …` 를 본다.

| 판정 | 기준 (max · mdev) | 예 |
|---|---|---|
| ✅ 합격 | **mdev 1ms 이하**, max 가 min 과 거의 같음 | OVH 캐나다: 76.7/76.9/77.0/**0.06** |
| ❌ 불합격 | max 가 min 의 몇 배, mdev 수십 ms | Contabo: 2.9/27.8/128/**35.4** |

- **거리(min)는 멀어도 괜찮다** (캐나다 → 유튜브 77ms 도 문제없음). **흔들림(mdev)이 작아야** 한다.
- 불합격이면 설치하지 말고 해지한다 (약정 없음으로 주문했으니 손해 없음).

## 4A. 새 서버: 설치 명령 1줄

`root@…#` 상태에서:

```bash
curl -fsSL https://raw.githubusercontent.com/alligogo/LiveMax/main/get.sh | bash
```

| 화면 | 하는 일 |
|---|---|
| `==> 1/5` | 프로그램(Docker 등) 설치 |
| `==> 2/5` | 시계 UTC · 유튜브 IPv4 우선 · **송출용 TCP(BBR + fq)** |
| `==> 3/5` | 방화벽(22·80·443) · 해킹 시도 차단 · 자동 보안 업데이트 (자동 재부팅·커널·Docker 제외) |
| `==> 4/5 SSH` | SSH 보안 (키로 접속했을 때만 비밀번호 로그인 끔) |
| `==> 5/5` | LiveMax 실행 + 재부팅해도 자동으로 켜짐 |

끝나면 **초록 상자**의 초기 비밀번호를 메모한다.

```
==================================================================
  LiveMax 설치 완료  (312초)
  접속:   https://서버IP
  아이디: admin
  초기 비밀번호: xxxxxxxxxxxxxxxxxxxx   (첫 로그인 때 바꾸게 됩니다)
==================================================================
```

노란 **[주의]**:

| 문구 | 할 일 |
|---|---|
| `SSH 키로 접속한 기록이 없어 비밀번호 로그인을 유지합니다` | 정상. (선택) 8번 SSH 키 |
| `커널 업데이트가 설치됐습니다 … reboot` | `reboot` → 1분 뒤 5번으로 |

> **설치 직후 재부팅은 바로 해도 된다 (권장).** 설치 중 보안 업데이트가 같이 깔려서 웹에
> `서버 재부팅 필요 (보안 업데이트 적용 대기)` 알림이 뜨는 경우가 많다. 라이브를 켜기 전인 지금이 끊김 없이 재부팅할 때다.
> `reboot` → SSH 창이 끊기는 게 정상 → 1~2분 뒤 웹 새로고침 (LiveMax 는 자동으로 켜지고, 데이터·비밀번호 그대로).
| `이 서버 커널은 BBR 을 지원하지 않음` | 그대로 진행해도 됨 (기본 방식으로 송출) |

같은 명령은 몇 번 다시 실행해도 안전하다 (데이터·비밀번호 유지).

## 4B. 서버 이전: 옛 서버 데이터를 통째로 옮기기

영상·음악·**스트림 키**·채널·라이브 설정·관리자 비밀번호·기록이 **전부 그대로** 넘어간다. 새로 등록할 것이 없다.
끊기는 시간은 **2차 복사 + 설치 몇 분**뿐이다 (유튜브 '자동 중지'를 꺼 뒀으면 같은 방송으로 이어짐).

> **반드시 순서대로.** 같은 스트림 키로 두 서버가 동시에 보내면 안 된다 → 옛 서버를 멈춘 **뒤에** 새 서버를 설치한다.

아래 `옛서버IP` 는 옛 서버(예: Contabo) IP. 명령은 **새 서버의 `root@…#`** 에서 실행한다 (③만 옛 서버).

**① 복사 도구 설치 (새 서버)**

```bash
apt-get update && apt-get install -y rsync
```

**② 1차 복사 — 옛 서버는 계속 송출 중 (새 서버)**

```bash
rsync -aHP root@옛서버IP:/opt/livemax/data/ /opt/livemax/data/
```

- 처음엔 `yes`, 그다음 **옛 서버 root 비밀번호**.
- 데이터 10GB 기준 서버끼리 10~20분. 끝날 때까지 기다린다.
- `Permission denied` 가 나오면 옛 서버가 비밀번호 접속을 막아 둔 것 → 화면 글자를 보내 주기.

**③ 옛 서버 송출 멈추기 (옛 서버에서)**

```bash
docker stop livemax
```

**④ 2차 복사 — 바뀐 것만, 1분 안쪽 (새 서버)**

```bash
rsync -aHP --delete root@옛서버IP:/opt/livemax/data/ /opt/livemax/data/
```

**⑤ 설치 → 자동 송출 시작 (새 서버)**

```bash
curl -fsSL https://raw.githubusercontent.com/alligogo/LiveMax/main/get.sh | bash
```

- 옮겨 온 데이터를 그대로 써서 라이브들이 **10초 간격으로 알아서 켜진다** (카드에 "시작 중" → "정상").
- 웹 비밀번호는 **옛 서버와 같다** (초록 상자에 초기 비밀번호가 안 나와도 정상).

**⑥ 옛 서버는 며칠 그대로 둔다**
- 새 서버에 문제가 생기면: 새 서버 `docker stop livemax` → 옛 서버 `docker start livemax` 로 즉시 되돌림.
- 며칠 문제없으면 옛 서버 해지.

## 6. 설치 후 확인 (라이브가 켜진 뒤)

**① 유튜브 연결이 BBR 로 붙었는지** — 켜진 라이브 수와 같은 숫자면 OK

```bash
ss -tni state established '( dport = :443 )' | grep -c bbr
```

**② 라이브를 켠 상태에서 회선이 여전히 깨끗한지** — 3단계와 비슷하면 OK

```bash
ping -4 -c 30 -q a.rtmps.youtube.com
```

- 라이브를 켠 **뒤에만** 흔들리기 시작하면 BBR 이 그 회선과 안 맞을 수 있다 → 결과를 보내 주기 (기본 방식 cubic 으로 바꿔 비교).

**③ CPU** — 웹 상단 미니 관제의 CPU. 라이브 10개 기준 평균 30~40% 면 정상.

**④ 하룻밤 뒤** — PC 측정기(`YT-Monitor.bat`)의 `_변화.txt` 에서 "나쁨" 횟수, 웹 알림의 밀림·재연결.

## 8. SSH 키로 보안 강화 (권장)

비밀번호 대신 PC 의 "열쇠 파일"로만 들어가게 한다. 인터넷에 열린 서버는 비밀번호 무작위 시도가 계속 들어오므로 해 두는 게 좋다.
**가장 좋은 때: 2번(접속·비밀번호 변경) 직후, 설치(4A/4B ⑤) 전.** 그러면 설치가 비밀번호 로그인을 자동으로 끈다.

**① 키 만들기 (PC 에서 한 번만)** — 새 PowerShell 창에서:

```powershell
ssh-keygen -t ed25519
```

질문 3번은 전부 **Enter**. `already exists` 라고 나오면 **`n`** — 예전에 만든 키가 이미 있다는 뜻이니 그대로 쓴다 (서버마다 새로 만들 필요 없음).
키는 PC 의 `C:\Users\내이름\.ssh\` 에 저장된다 (`id_ed25519` = 열쇠, **절대 남에게 주지 않기** / `id_ed25519.pub` = 자물쇠, 서버에 올리는 것).

**② 서버에 자물쇠 올리기** (`ubuntu` 자리는 Contabo 면 `root`):

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ubuntu@서버IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

서버 비밀번호를 한 번 넣는다.

**③ 비밀번호 없이 들어가지는지 확인**

```powershell
ssh ubuntu@서버IP
```

비밀번호를 묻지 않으면 성공. 이 상태(키로 접속한 창)에서 `sudo -i` 후 설치(4A, 또는 4B ⑤)를 하면
`4/5 SSH` 에 `비밀번호 로그인 끔 (키 인증 전용)` 이 나온다. 이미 설치한 서버라면 설치 명령을 한 번 더 실행한다
(LiveMax 가 1~2분 재시작되니 한가한 때에).

> - 이후엔 **키가 있는 PC 에서만** SSH 접속이 된다. 다른 PC 를 쓰려면 그 PC 에서 ①②를 해서 자물쇠를 추가한다.
> - PC 를 바꾸거나 포맷하기 전에 `C:\Users\내이름\.ssh\` 폴더를 USB 등에 **백업**해 둔다 (잃으면 업체 관리 화면의 콘솔로 들어가 다시 등록해야 함).
> - 웹(`https://서버IP`)은 상관없이 어디서나 된다. `LiveMax-SSH.bat` 도 키로 자동 접속된다.

## 9. 미디어 올리기

1. PC에서 원본을 **`LiveMax-Convert.bat`에 끌어다 놓아** 규격대로 변환한다 (아래 "PC 변환기").
2. 대시보드 **비디오** 탭 → 폴더 만들기 → 폴더 선택 → `LiveMax_변환` 폴더의 MP4 를 끌어다 놓기
3. **음악** 탭도 같은 방식으로 M4A 를 올린다.
4. 올린 파일은 자동으로 규격 검사를 거친다. 통과하면 목록에, 실패하면 아래 **검증 실패**에 이유가 나온다.

큰 파일도 업로드가 끊기면 **이어서** 올라간다 (같은 파일을 다시 끌어다 놓으면 남은 부분만).

### WinSCP 로 많이 올릴 때

파일이 많거나 크면 WinSCP 가 편하다. **반드시 '업로드 대기' 폴더로** 올린다 — 방송 폴더(`media/video/…`)에 직접 넣으면 검사를 건너뛴다.

| 종류 | 올릴 위치 |
|---|---|
| 비디오 | `/opt/livemax/data/media/_incoming/video/폴더이름/` |
| 음악 | `/opt/livemax/data/media/_incoming/audio/폴더이름/` |

- 폴더는 **먼저 웹에서** 만든다 (그래야 대기 폴더도 생긴다). PC 폴더 이름을 웹 폴더와 똑같이 해 두면 `_incoming/video/` 에 폴더째 끌어다 놓아도 된다.
- WinSCP 설정: 옵션 → 환경 설정 → 전송 → 백그라운드 → **기본적으로 백그라운드에서 전송** 체크.
- 위 두 경로를 WinSCP **책갈피**로 저장해 두면 실수가 없다.

**같은 이름 규칙 — 덮어쓰지 않는다.** 그 파일이 지금 송출 중일 수 있기 때문이다.

| 올린 파일 | 결과 (웹 '검증 실패'에 이유 표시) |
|---|---|
| 폴더에 같은 이름이 이미 있음 (대소문자 무시) | **거부** — 교체하려면 웹에서 기존 파일을 지우고 다시 올린다 |
| 이름은 다르지만 내용이 같은 파일이 있음 | **거부** (중복) |

방송 폴더에 직접 넣거나 바꾼 파일은 서버가 1분마다 찾아내서 알림으로 알려 준다 (규격이 맞으면 등록, 원본은 옮기거나 지우지 않음).

## 10. 라이브 추가

(7번에서 채널·스트림 키를 먼저 등록해 둔다.) **라이브** 탭 → **+ 라이브 추가**

| 칸 | 넣을 것 |
|---|---|
| 이름 | 아무거나 (예: 재즈 색소폰 24/7) |
| 채널 · 스트림 키 | 채널을 고르고 그 채널에 등록한 키 중 하나 (다른 라이브가 쓰는 키는 못 고름) |
| 비디오 폴더 / 음악 폴더 | 체크 (여러 개 가능) |
| 재생 방식 | 그대로 (중복방지 랜덤) |
| 타이머 | 끄기(24시간 계속) / 방송 시간(예: 11시간 50분, 반복 가능) / 종료 시각 |

**저장하고 시작** → 몇 초 뒤 카드가 ● 정상으로 바뀌면 송출 중이다.

유튜브 스트림 설정 (라이브마다):

| 쓰는 방식 | 자동 시작 | 자동 중지 |
|---|---|---|
| 타이머 끔 — 하나의 방송을 계속 | 켬 | **끔** (재시작 공백에 방송이 끝나지 않게) |
| 타이머 켬 — 12시간 다시보기를 남김 | 켬 | **켬** (송출이 멈추면 방송 종료 → 다시보기 저장) |

타이머 + 자동 중지를 쓸 때는 처음 한 번 **재시작 버튼**을 눌러 2~3초 공백에도 방송이 이어지는지 유튜브 스튜디오에서 확인해 두자.

## PC 변환기 (`tools/windows/LiveMax-Convert.bat`)

GitHub 저장소 → Code → Download ZIP → 압축 풀기 → `tools/windows/LiveMax-Convert.bat` (바탕화면에 바로 가기 추천).

- 영상·음악 파일이나 **폴더**를 끌어다 놓으면 원본 옆 `LiveMax_변환` 폴더에 같은 이름으로 생긴다.
- 영상: H.264 1080p 30fps 5000k, 키프레임 2초, 소리 제거 / 음악: AAC 128k 44.1kHz, -14 LUFS (서버는 128k~192k 를 받음)
- 100개가 넘으면 폴더째 끌어다 놓는다. ffmpeg 가 필요하다 (`winget install Gyan.FFmpeg`).

## PC 서버 관리 도구 (`tools/windows/LiveMax-SSH.bat`)

SSH 명령을 외우지 않아도 되게 번호로 고르는 도구다. GitHub ZIP 의 `tools/windows/LiveMax-SSH.bat` 을 받아서:

1. 메모장으로 열어 맨 위 `$Servers` 에 서버를 적고 저장 (서버가 늘면 줄을 추가)
   ```
   @{ Name = "LIVE 1"; Host = "옛서버IP" }
   @{ Name = "LIVE 2"; Host = "새서버IP"; User = "ubuntu" }   # OVH 는 ubuntu (root 가 아니면 명령에 sudo 자동)
   ```
2. 더블클릭 → 서버 번호 → 할 일 번호
   - 접속 / 웹 열기 / 상태 / 로그 / **관리자 비밀번호 재설정** / **LiveMax 다시 시작(웹이 안 열릴 때)** / 업데이트 / **서버 재부팅**
   - R: 서버를 다시 설치해서 접속 경고가 날 때 (PC 에 저장된 서버 지문 지우기)
3. 재시작·재부팅·비밀번호 재설정은 한 번 더 확인(y)을 받는다.

> 진짜 IP 는 내 PC 의 사본에만 적는다. GitHub 에는 예시만 있다.

## 서버에서 쓰는 명령 (가끔)

```bash
livemax status      # 상태
livemax logs -f     # 실시간 로그
sudo livemax update # 업데이트 (웹 버튼과 같음)
sudo livemax password
```

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| `ssh` 가 한참 멈췄다가 `timed out` | 업체 관리 화면에서 서버가 켜져 있는지(Running/Active), IP 가 맞는지 확인 |
| `Permission denied` | 아이디(OVH `ubuntu` / Contabo `root`) 또는 비밀번호가 틀림 (화면에 안 보여도 입력되고 있다). 업체 관리 화면에서 비밀번호 재설정 가능 |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED` | 같은 IP 에 서버를 다시 깔았을 때 나온다. PowerShell 에서 `ssh-keygen -R 서버IP` 후 다시 접속 |
| 설치 중 빨간 **[중단]** | 화면 글자를 복사해서 보내 주기. 같은 명령 재실행은 안전 |
| `https://서버IP` 가 안 열림 | 서버에서 `livemax status` → `Up` 이 아니면 `sudo livemax restart`. 그래도 안 되면 `livemax logs` 결과 보내 주기 |
| "안전하지 않음" 이 10분 넘게 계속 | 인증서 발급이 막힌 경우. 경고 화면의 "고급 → 계속" 으로도 접속은 된다 (암호화는 됨). `livemax logs` 결과 보내 주기 |
| 관리자 비밀번호를 잊음 | 서버에 접속해서 `sudo livemax password` → 새 임시 비밀번호가 나온다 |
