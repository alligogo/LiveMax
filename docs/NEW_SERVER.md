# 새 서버 오픈 매뉴얼

서버를 늘릴 때마다 이 문서만 순서대로 따라 하면 된다. 윈도우 PC 기준이다.

반복 작업은 PC의 **LiveMax 메뉴**(`LiveMax.bat`)가 대신한다. 사람이 하는 일은 아래 ✋ 표시뿐이다.

| | 서버 1대당 하는 일 | 걸리는 시간 |
|---|---|---|
| ✋ | Contabo 주문 | 5분 |
| 🤖 | 메뉴 2: 새 서버 설치 (비밀번호 1번만 입력하고 기다리기) | 15~20분 (자동) |
| ✋ | 유튜브 스트림 키 준비 | 5분 |
| ✋ | 대시보드: 비밀번호 변경 → 폴더 → 미디어 → 라이브 설정 | 15분~ |
| 🤖 | 메뉴 4: 라이브 시작 → 메뉴 5: 상태 점검 | 2분 |

---

## A. 최초 1회만 — PC 준비

이미 했으면 B로 넘어간다.

### A-1. PC 도구 받기

1. GitHub 저장소 페이지 → 초록색 **Code** 버튼 → **Download ZIP**
2. 받은 ZIP을 오른쪽 클릭 → **압축 풀기** → `C:\LiveMax`에 푼다
3. `C:\LiveMax\LiveMax-main\tools\windows\LiveMax.bat` 파일이 있으면 된다
4. (편하게) `LiveMax.bat`을 오른쪽 클릭 → **바로 가기 만들기** → 바로 가기를 바탕화면으로 옮긴다

> PC 도구가 업데이트됐다고 안내받았을 때만 ZIP을 다시 받는다. 서버 목록과 키는 다른 곳(`C:\Users\내이름\livemax`, `.ssh`)에 있어서 다시 받아도 지워지지 않는다.

### A-2. 메뉴 1: PC 준비

`LiveMax.bat` 더블클릭 → `1` 입력 → Enter

| 화면 질문 | 입력 |
|---|---|
| SSH 키 만들기 질문 (이미 있으면 생략됨) | Enter 3번 |
| `등록된 서버의 IP` | 이미 GitHub 등록을 마친 서버(live1)의 IP. 예: `13.140.201.245` |
| `그 서버 이름을 목록에 추가할까요?` | `live1` |

마지막에 `GitHub 연결 OK — 새 서버 설치 준비 완료`가 나오면 끝이다.

> 이 과정에서 live1의 GitHub 키(읽기 전용)를 PC로 가져온다. 이후 모든 새 서버에는 이 키를 복사해 쓰기 때문에, **GitHub 등록과 폰 인증은 다시 할 필요가 없다.**

### A-3. WinSCP 설치 (미디어 업로드용, 선택)

대용량 파일을 탐색기처럼 끌어다 올릴 때 쓴다.

1. https://winscp.net 에서 설치한다
2. 첫 실행 → **새 사이트**
   - 파일 프로토콜: **SFTP**
   - 호스트 이름: 서버 IP
   - 사용자 이름: `root`
   - 비밀번호: **비워 둔다**
3. **고급** → 왼쪽 **SSH → 인증** → **개인키 파일** 옆 `...` → `C:\Users\내이름\.ssh\id_ed25519` 선택
   - 파일 형식을 **모든 파일(*.*)** 로 바꿔야 보인다
   - "PuTTY 형식으로 변환할까요?" → **예** → 같은 폴더에 저장 → **확인**
4. **저장** → 이름을 `live2` 처럼 서버 이름으로 → **로그인**

서버마다 2~4를 반복한다. 변환한 개인키 파일은 재사용하면 된다.

## B. 서버 1대 추가할 때마다

### B-1. ✋ Contabo 주문

| 항목 | 선택 |
|---|---|
| 상품 | **Cloud VPS 4** |
| 기간 | 1 Month |
| 리전 | **European Union** |
| 이미지 | **Ubuntu 24.04** (다른 버전 금지) |
| 로그인 | root 비밀번호 설정 → **메모장에 적어 두기** |
| 나머지 추가 옵션 | 선택 안 함 |

주문 후 패널 **Compute → VPS**에서 상태가 **Running**이 되면 **IP Address**를 복사한다.

### B-2. 🤖 메뉴 2: 새 서버 설치

`LiveMax.bat` → `2`

| 화면 질문 | 입력 |
|---|---|
| `서버 이름` | `live2`, `live3` … 순서대로 (영문 소문자·숫자·`-`) |
| `서버 IP` | B-1에서 복사한 IP |
| `password:` | B-1의 root 비밀번호 (**화면에 안 보이는 게 정상**, 입력 후 Enter) |

비밀번호는 이때 **딱 한 번만** 입력한다. 나머지는 자동으로 진행된다:

1. SSH 키 등록 → 키 접속 확인
2. OS 확인 (Ubuntu 24.04가 아니면 멈춤)
3. 서버 최초 설정: 업데이트, UTC, 방화벽, fail2ban, 자동 업데이트 정책, 비밀번호 로그인 끄기
4. 코드 받기 → LiveMax 설치
5. 필요하면 재부팅 (새 서버라 송출 영향 없음)

끝나면 초록색 박스에 **대시보드 초기 비밀번호**가 나온다. **메모장에 적는다.**

> 중간에 빨간 `[실패]`가 나오면 그 화면 전체를 복사해서 질문한다. 같은 메뉴를 다시 실행해도 안전하다(이미 된 단계는 건너뜀).

### B-3. ✋ 유튜브 준비 (이 서버가 맡을 채널)

유튜브 스튜디오 → **만들기 → 라이브 스트리밍 시작** → **스트림** 탭

- 라이브 1개당 **스트림 키 1개**가 필요하다. 한 채널에 라이브를 여러 개 띄우려면 스트림 키 선택 → **새 스트림 키 만들기**로 개수만큼 만든다. 키 이름은 `ch01`, `ch02`처럼 라이브 ID와 맞추면 헷갈리지 않는다.
- 각 스트림 설정에서 **자동 시작: 켬**, **자동 중지: 끔**으로 한다.
  - 자동 중지가 켜져 있으면 일일 재시작 때마다 방송이 끝나 버린다.
- 각 스트림 키를 복사해 둔다. 이 키는 남에게 보이면 안 된다.

### B-4. ✋ 대시보드 열기 + 비밀번호 변경

`LiveMax.bat` → `3` → 서버 번호 선택 → 브라우저가 자동으로 열린다

1. 아이디 `admin`, B-2의 초기 비밀번호로 로그인
2. 새 비밀번호(12자 이상)로 변경한다. 서버별 비밀번호는 비밀번호 관리자 등에 보관한다.

> 대시보드를 다 쓰면 검은 창에서 Enter를 눌러 연결을 끊는다. 창을 그냥 닫아도 된다.

### B-5. ✋ 폴더 만들기 + 미디어 올리기

1. 대시보드 **영상** 탭 → 폴더 만들기 (예: `morning`, `night`)
2. **음원** 탭 → 폴더 만들기 (예: `chill`)
3. 파일 올리기 (둘 중 하나)
   - **웹:** 폴더 선택 → 파일을 끌어다 놓기
   - **WinSCP (대용량 권장):** 오른쪽(서버) 창에서 `/media/_incoming/video/<폴더>/` 또는 `/media/_incoming/audio/<폴더>/`로 이동 → 왼쪽(PC)에서 파일을 끌어다 놓기
4. 30초쯤 뒤 대시보드에서 폴더를 다시 연다
   - 통과한 파일은 목록에 나온다
   - 실패한 파일은 **검증 실패**에 이유와 함께 나온다 (예: "샘플레이트 48000 Hz — 44100 Hz 여야 함")

> 방송 폴더(`/media/video`, `/media/audio`)에는 직접 올리지 않는다. 반드시 `_incoming` 쪽으로 올린다.

### B-6. ✋ 라이브 설정

**방법 1 — 다른 서버 설정을 재사용 (추천)**
1. 기존 서버 대시보드 → **설정 → 설정 내보내기** → zip 저장
2. 새 서버 대시보드 → **설정 → 설정 가져오기** → zip 선택 → 가져오기
3. 가져온 라이브는 **비활성 + 스트림 키 없음** 상태다. **스트리밍**에서 라이브마다:
   - 이름 수정, 스트림 키 붙여넣기(B-3), **송출 활성화** 체크 → 저장

**방법 2 — 새로 만들기**
**스트리밍 → + 라이브 추가**. 입력값은 저장소 README의 7단계 표를 참고한다.

**어느 방법이든 꼭 지킬 것**
- **일일 재시작 시각**은 라이브마다 다르게 한다 (예: 04:17, 04:19, 04:21 …). 겹치면 저장이 거부된다.
- **오디오 내부 포트**도 라이브마다 다르게 한다 (8101, 8102 …). 새로 만들면 자동으로 채워진다.

### B-7. 🤖 메뉴 4: 라이브 시작 → 메뉴 5: 상태 점검

1. `LiveMax.bat` → `4` → 서버 선택
   - 활성 라이브를 **31초 간격으로 하나씩** 시작한다. 이미 송출 중인 라이브는 건드리지 않는다.
2. 1~2분 뒤 `LiveMax.bat` → `5` → 서버 선택
   - 마지막에 `결과: 송출 준비 OK`가 나오면 정상이다
3. 유튜브 스튜디오 스트림 탭에서 상태 **정상**과 미리보기를 확인한다

## C. 평소 관리

| 언제 | 할 일 |
|---|---|
| 매일 1~2번 | 서버별 대시보드(메뉴 3)에서 경고 확인. 폰에서도 된다 |
| 코드 업데이트 안내를 받았을 때 | 메뉴 6 → `a` (전체). 송출 중인 라이브는 재시작하지 않는다 |
| 대시보드에 **"재부팅 필요"** 가 떴을 때 | 송출 영향이 적은 시간에 메뉴 7(서버 접속) → `sudo apt update && sudo apt upgrade` → `sudo reboot`. 서버 한 대씩 한다 |
| 라이브 추가·활성화 후 | 메뉴 4 (라이브 시작) |
| 이상할 때 | 메뉴 5 (상태 점검) 결과를 복사해서 질문 |

## D. 문제 해결

| 증상 | 해결 |
|---|---|
| `ssh 프로그램이 없습니다` | 윈도우 설정 → 시스템 → 선택적 기능 → 기능 추가 → **OpenSSH 클라이언트** 설치 |
| 메뉴 2에서 `접속 실패 — IP·비밀번호를 확인하세요` | 서버가 Running인지, IP·root 비밀번호가 맞는지 확인 후 메뉴 2를 다시 실행 |
| `Ubuntu 24.04 가 아닙니다` | Contabo 패널 → 해당 VPS → **Reinstall** → Ubuntu 24.04 → 메뉴 2를 다시 실행 |
| `GitHub 연결 실패` | 메뉴 1(PC 준비)을 다시 실행해서 `GitHub 연결 OK`가 나오는지 확인 |
| PC를 바꿨거나 `.ssh` 폴더를 잃어버림 | 백업해 둔 `.ssh` 폴더를 `C:\Users\내이름\`에 복원한다. 백업이 없으면 Contabo 패널의 **VNC 콘솔**로 서버에 들어가 새 PC 공개키를 `/root/.ssh/authorized_keys`에 추가한다 |
| 대시보드 다른 서버로 바꿨더니 다시 로그인하라고 함 | 정상이다 (PC 쪽 주소가 같은 localhost라 로그인 정보가 공유됨) |
