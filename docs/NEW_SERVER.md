# 새 서버 오픈 매뉴얼 (v2)

서버를 하나 더 늘릴 때 **이 순서대로만** 하면 된다. 도스창 도구, GitHub 등록, 설정 파일 편집은 필요 없다.
PC는 **Windows** 기준이다.

| 순서 | 할 일 | 누가 | 시간 |
|---|---|---|---|
| 1 | Contabo 에서 서버 주문 | 나 | 5분 |
| 2 | PowerShell 로 서버 접속 | 나 | 1분 |
| 3 | 설치 명령 1줄 붙여넣기 | **자동** | 5~10분 |
| 4 | 웹 접속 → 비밀번호 변경 → 서버명 | 나 | 2분 |
| 5 | (선택) SSH 키로 보안 강화 | 나 | 3분 |
| 6 | 채널·키 등록 → 미디어 올리기 → 라이브 추가 | 나 | 파일 양에 따라 |

> 처음 해 보는 새 서버라면 3번 설치 화면에서 막히거나 빨간 **[중단]** 이 보일 때, 그 화면 글자를 그대로 복사해서 보내 주면 된다.

## 1. Contabo 에서 서버 주문

| 항목 | 고를 것 |
|---|---|
| 상품 | **Cloud VPS 4** (4 vCPU / 8GB) |
| 리전 | European Union (지금 서버와 같게) |
| 이미지(OS) | **Ubuntu 24.04** |
| 로그인 | **root 비밀번호**를 정해서 메모장에 적어 둔다 |

주문 후 Contabo 패널에서 상태가 **Running** 으로 바뀌면(보통 5~15분) **IP Address**(예: `13.140.201.245`)를 복사한다.

## 2. PowerShell 로 서버 접속

1. 키보드 **윈도우 키** → `powershell` 입력 → **Enter**
2. 파란(또는 검은) 창에 아래처럼 입력한다. `서버IP` 자리에 복사한 IP 를 넣는다.

```powershell
ssh root@서버IP
```

3. 처음 접속하면 영어 질문이 하나 나온다 → `yes` 입력 → **Enter**
4. `password:` 가 나오면 1번에서 정한 root 비밀번호를 입력 → **Enter**
   - **입력해도 화면에 아무것도 안 보이는 게 정상이다.** 그냥 치고 Enter.
   - 붙여넣기는 **마우스 오른쪽 클릭** 한 번이다 (Ctrl+V 가 안 될 수 있음).
5. 맨 아래 줄이 `root@vmi…:~#` 처럼 바뀌면 서버 안에 들어온 것이다.

---

## 3. 설치 명령 1줄 (자동)

서버 안에서 아래 한 줄을 **복사 → 마우스 오른쪽 클릭으로 붙여넣기 → Enter**:

```bash
curl -fsSL https://raw.githubusercontent.com/alligogo/LiveMax/main/get.sh | bash
```

화면에 다섯 단계가 차례로 지나간다. 그냥 기다리면 된다 (5~10분).

| 화면에 보이는 것 | 하는 일 |
|---|---|
| `==> 1/5 …` | 필요한 프로그램(Docker 등) 설치 |
| `==> 2/5 …` | 서버 시계·인터넷 설정 (유튜브 연결 안정화용 IPv4 우선) |
| `==> 3/5 …` | 방화벽(22·80·443만 열기), 해킹 시도 차단, 자동 보안 업데이트 (방송을 끊는 자동 재부팅·커널·Docker 는 제외) |
| `==> 4/5 SSH` | SSH 보안 설정 (아래 노란 문구 설명 참고) |
| `==> 5/5 LiveMax 실행` | LiveMax 를 받아 실행, 재부팅해도 자동으로 켜지게 등록 |

끝나면 **초록 상자**가 나온다. **초기 비밀번호를 메모장에 복사해 둔다.**

```
==================================================================
  LiveMax 설치 완료  (312초)
  접속:   https://서버IP
  아이디: admin
  초기 비밀번호: xxxxxxxxxxxxxxxxxxxx   (첫 로그인 때 바꾸게 됩니다)
==================================================================
```

### 노란 [주의] 문구가 보이면

| 문구 | 뜻 / 할 일 |
|---|---|
| `SSH 키로 접속한 기록이 없어 비밀번호 로그인을 유지합니다` | 정상이다. 비밀번호로 접속했기 때문. 보안을 더 올리고 싶으면 5번(선택)을 하면 된다. |
| `커널 업데이트가 설치됐습니다 … 'reboot' 하면 깔끔합니다` | `reboot` 입력 → Enter. 창이 끊긴다. **1분 기다린 뒤** 웹 접속(4번)으로 넘어가면 된다. LiveMax 는 재부팅 뒤 자동으로 켜진다. |

빨간 **[중단]** 이 나오면 화면 글자를 그대로 복사해서 보내 주면 된다. 같은 명령을 다시 실행해도 안전하다 (데이터·비밀번호는 그대로 남는다).

---

## 4. 웹 접속 → 비밀번호 변경 → 서버명

1. 브라우저 주소창에 `https://서버IP` 입력
   - 설치 직후 1~2분은 인증서를 받는 중이라 **"안전하지 않음"** 경고가 보일 수 있다. 1~2분 뒤 새로고침하면 사라진다.
2. 아이디 `admin` + 초록 상자의 **초기 비밀번호** → 로그인
3. 바로 **새 비밀번호(12자 이상)** 로 바꾸라는 창이 뜬다 → 바꾼다. (이 비밀번호는 잊지 않게 따로 보관)
4. 위 메뉴 **설정 → 서버** → **서버명**(예: `LIVE 2`) → 저장
   - 로고 옆, 브라우저 탭 제목, 휴대폰 알림 제목에 붙어서 서버끼리 구분된다.
5. (선택) **설정 → 모바일 알림** 에 Pushbullet 토큰을 넣고 테스트 알림 보내기.

휴대폰에서도 같은 주소로 들어간다. 서버마다 즐겨찾기에 이름 붙여 저장해 두면 편하다.

**여기까지가 서버 세팅 끝이다.** 이 뒤 업데이트는 웹의 **설정 → 최신 버전으로 업데이트** 버튼만 누르면 된다.

## 5. (선택) SSH 키로 보안 강화

비밀번호 대신 PC 에 저장된 "열쇠 파일"로만 서버에 들어가게 하는 설정이다. 안 해도 동작에는 문제없지만, 해 두면 비밀번호를 무작위로 시도하는 공격이 아예 통하지 않는다.

PC 의 PowerShell 에서 (서버 안이 아니라 **새 PowerShell 창**에서):

```powershell
ssh-keygen -t ed25519
```

질문이 3번 나오면 전부 그냥 **Enter** (이미 키가 있다고 나오면 `n` 하고 다음으로).

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@서버IP "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

root 비밀번호를 한 번 더 넣는다. 그다음 **비밀번호 없이** 들어가지는지 확인:

```powershell
ssh root@서버IP
```

비밀번호를 묻지 않고 들어가지면, 서버 안에서 설치 명령(3번)을 **한 번 더** 실행한다 (다시 실행하면 LiveMax 가 1~2분 재시작되므로 **라이브를 시작하기 전에** 하는 게 좋다. 관리자 비밀번호는 그대로 유지된다). 이번에는 `4/5 SSH` 단계에서 `비밀번호 로그인 끔 (키 인증 전용)` 이 나온다. 끝.

> 주의: 이후로는 **그 PC(키 파일이 있는 PC)에서만** 서버에 접속된다. 다른 PC 에서도 접속하려면 그 PC 에서도 위 과정을 해서 키를 추가한다. 웹 관리 화면(`https://서버IP`)은 상관없이 어디서나 된다.

## 6. 미디어 올리기

1. PC에서 원본을 **`LiveMax-Convert.bat`에 끌어다 놓아** 규격대로 변환한다 (아래 "PC 변환기").
2. 대시보드 **비디오** 탭 → 폴더 만들기 → 폴더 선택 → `LiveMax_변환` 폴더의 MP4 를 끌어다 놓기
3. **음악** 탭도 같은 방식으로 M4A 를 올린다.
4. 올린 파일은 자동으로 규격 검사를 거친다. 통과하면 목록에, 실패하면 아래 **검증 실패**에 이유가 나온다.

큰 파일도 업로드가 끊기면 **이어서** 올라간다 (같은 파일을 다시 끌어다 놓으면 남은 부분만).

## 7. 라이브 추가

먼저 **채널** 탭 → **+ 채널 추가** → 채널명·주소·로고 → 그 채널 카드에서 **스트림 키 등록** (키는 여기서만 넣는다).

그다음 **라이브** 탭 → **+ 라이브 추가**

| 칸 | 넣을 것 |
|---|---|
| 이름 | 아무거나 (예: 재즈 색소폰 24/7) |
| 채널 · 스트림 키 | 채널을 고르고 그 채널에 등록한 키 중 하나 (다른 라이브가 쓰는 키는 못 고름) |
| 비디오 폴더 / 음악 폴더 | 체크 (여러 개 가능) |
| 재생 방식 | 그대로 (중복방지 랜덤) |
| 타이머 | 끄기(24시간 계속) / 방송 시간(예: 11시간 50분, 반복 가능) / 종료 시각 |

**저장하고 시작** → 몇 초 뒤 카드가 ● 정상으로 바뀌면 송출 중이다.

유튜브 스트림 설정 (라이브마다):

| 쓰는 방식 | 자동 시작 | 자동 중지 |
|---|---|---|
| 타이머 끔 — 하나의 방송을 계속 | 켬 | **끔** (재시작 공백에 방송이 끝나지 않게) |
| 타이머 켬 — 12시간 다시보기를 남김 | 켬 | **켬** (송출이 멈추면 방송 종료 → 다시보기 저장) |

타이머 + 자동 중지를 쓸 때는 처음 한 번 **재시작 버튼**을 눌러 2~3초 공백에도 방송이 이어지는지 유튜브 스튜디오에서 확인해 두자.

## PC 변환기 (`tools/windows/LiveMax-Convert.bat`)

GitHub 저장소 → Code → Download ZIP → 압축 풀기 → `tools/windows/LiveMax-Convert.bat` (바탕화면에 바로 가기 추천).

- 영상·음악 파일이나 **폴더**를 끌어다 놓으면 원본 옆 `LiveMax_변환` 폴더에 같은 이름으로 생긴다.
- 영상: H.264 1080p 30fps 5000k, 키프레임 2초, 소리 제거 / 음악: AAC 128k 44.1kHz, -14 LUFS (서버는 128k~192k 를 받음)
- 100개가 넘으면 폴더째 끌어다 놓는다. ffmpeg 가 필요하다 (`winget install Gyan.FFmpeg`).

## PC 서버 관리 도구 (`tools/windows/LiveMax-SSH.bat`)

SSH 명령을 외우지 않아도 되게 번호로 고르는 도구다. GitHub ZIP 의 `tools/windows/LiveMax-SSH.bat` 을 받아서:

1. 메모장으로 열어 맨 위 `$Servers` 에 서버를 적고 저장 (서버가 늘면 줄을 추가)
   ```
   @{ Name = "LIVE 1"; Host = "13.140.201.245" }
   @{ Name = "LIVE 2"; Host = "새서버IP" }
   ```
2. 더블클릭 → 서버 번호 → 할 일 번호
   - 접속 / 웹 열기 / 상태 / 로그 / **관리자 비밀번호 재설정** / **LiveMax 다시 시작(웹이 안 열릴 때)** / 업데이트 / **서버 재부팅**
   - R: 서버를 다시 설치해서 접속 경고가 날 때 (PC 에 저장된 서버 지문 지우기)
3. 재시작·재부팅·비밀번호 재설정은 한 번 더 확인(y)을 받는다.

> 진짜 IP 는 내 PC 의 사본에만 적는다. GitHub 에는 예시만 있다.

## 서버에서 쓰는 명령 (가끔)

```bash
livemax status      # 상태
livemax logs -f     # 실시간 로그
sudo livemax update # 업데이트 (웹 버튼과 같음)
sudo livemax password
```

## 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| `ssh` 가 한참 멈췄다가 `timed out` | Contabo 패널에서 서버가 **Running** 인지, IP 가 맞는지 확인 |
| `Permission denied` | root 비밀번호가 틀림 (화면에 안 보여도 입력되고 있다). Contabo 패널에서 비밀번호 재설정 가능 |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED` | 같은 IP 에 서버를 다시 깔았을 때 나온다. PowerShell 에서 `ssh-keygen -R 서버IP` 후 다시 접속 |
| 설치 중 빨간 **[중단]** | 화면 글자를 복사해서 보내 주기. 같은 명령 재실행은 안전 |
| `https://서버IP` 가 안 열림 | 서버에서 `livemax status` → `Up` 이 아니면 `sudo livemax restart`. 그래도 안 되면 `livemax logs` 결과 보내 주기 |
| "안전하지 않음" 이 10분 넘게 계속 | 인증서 발급이 막힌 경우. 경고 화면의 "고급 → 계속" 으로도 접속은 된다 (암호화는 됨). `livemax logs` 결과 보내 주기 |
| 관리자 비밀번호를 잊음 | 서버에 접속해서 `sudo livemax password` → 새 임시 비밀번호가 나온다 |
